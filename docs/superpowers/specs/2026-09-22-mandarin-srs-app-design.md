# Mandarin Speaking Drill App — Design

Date: 2026-09-22

## Purpose

A personal, phone-first practice app for phrases from weekly Mandarin coaching sessions. The priority is being able to **say** things (production), with secondary support for recognising them by ear and by sight. New material arrives weekly as messy coach notes; Claude turns those into structured data, audio, and a deploy.

## Learning principles (drive every design choice)

1. **Active recall over recognition** — the main card is English → say Mandarin aloud → reveal.
2. **Spaced repetition** — FSRS scheduling (ts-fsrs).
3. **Audio-first** — every item has native-sounding audio at normal and slow speed; audio auto-plays on reveal.
4. **Pattern drills** — sentence frames (我喜歡喝___) are practised with rotating known vocabulary, so the learner builds sentences instead of reciting fixed strings.
5. **Short daily sessions** — ~20 cards, 5–10 minutes, one tap from the home screen.

## Users and constraints

- Single user, a Dutch professor teaching at CUHK (Hong Kong), learning Mandarin from a Taiwanese coach.
- **Traditional characters** throughout. **Taiwan Mandarin** pronunciation; the coach's pinyin is authoritative where it differs from mainland norms (e.g. 法國 Fàguó, 什麼 shéme as given).
- Primary device: phone (iPhone assumed). Must work offline.
- Phrases are added by Claude from pasted notes, not through an in-app form.

## User experience

### Home
- Count of cards due today, big **Start** button, streak counter, number of items learned.
- Tabs: **Study**, **Browse**, **Settings**.

### Card types (all generated from the same item list)
| Type | Prompt | Answer | Available |
|---|---|---|---|
| **Say it** | English meaning (+ usage note) | characters, tone-coloured pinyin, audio auto-plays | always (for every item) |
| **Listen** | audio only (replay button) | characters, pinyin, English | after the item's Say-it card has been graded Good/Easy ≥ 2 times |
| **Read** | characters only | pinyin, English, audio | same unlock rule as Listen |

Grading: **Again / Hard / Good / Easy** (FSRS ratings 1–4).

A 🐢 button replays the slow audio on any revealed card.

### Pattern cards
A pattern item (e.g. 我喜歡喝{drink}) has one Say-it card in the scheduler. Each time it's shown, it is filled with a random vocabulary word from the slot's category that the learner has already *introduced* (has seen at least once). If no introduced filler exists yet, any filler in that category is used.

### Display details
- Pinyin coloured by tone: 1 red, 2 orange, 3 green, 4 blue, neutral grey.
- 不/一 tone changes shown in the pinyin as spoken (不要 bú yào, 一點點 yì diǎndiǎn).
- Optional per-item `note` shown on reveal (e.g. 二 vs 兩).

### Browse
List of all items grouped by week, each tappable to play audio. Shows characters, pinyin, English.

### Settings
- New cards per day (default 10).
- Export progress (downloads JSON) / Import progress (file picker).
- A banner asks for a weekly export when the last export was more than 7 days ago.

## Architecture

Static site, no framework, no build step for the frontend.

```
index.html            app shell
app.js                UI + session flow
lib/cards.js          card generation, unlock rules, pattern filling (pure functions)
lib/srs.js            thin wrapper over ts-fsrs
lib/store.js          localStorage persistence + export/import
lib/tones.js          tone number extraction for colouring
vendor/ts-fsrs.js     vendored library (offline)
styles.css
sw.js                 service worker: cache-first for shell + audio, network-first for phrases.json
manifest.webmanifest  home-screen install
phrases.json          GENERATED by tools/build.py — do not hand-edit
data/items.json       SOURCE of truth — hand-edited (by Claude) each week
audio/{id}.mp3, audio/{id}-slow.mp3   generated
audio/coach/{id}.mp3  optional coach recordings; override generated audio
tools/build.py        validate → expand patterns → apply sandhi → generate missing audio → write phrases.json
tests/                JS tests (node:test) + Python tests (unittest)
```

### Source data (`data/items.json`)
```json
{
  "items": [
    {"id": "xiexie", "kind": "phrase", "week": 1, "zh": "謝謝", "pinyin": "xièxie", "en": "Thank you"},
    {"id": "kafei", "kind": "word", "week": 1, "zh": "咖啡", "pinyin": "kāfēi", "en": "coffee", "cat": ["drink"]},
    {"id": "wo-xihuan-he-x", "kind": "pattern", "week": 1, "zh": "我喜歡喝{drink}", "pinyin": "wǒ xǐhuān hē {drink}", "en": "I like drinking {drink}"}
  ]
}
```
- `id`: stable ASCII slug; never changes once published (progress is keyed by it).
- `kind`: `word` | `phrase` | `pattern`.
- `cat`: optional list of slot categories a word can fill.
- `pinyin`: written with base (dictionary) tones; sandhi applied by the build.
- `note`: optional string.

### Build output (`phrases.json`)
```json
{
  "version": "2026-09-22T12:00:00Z",
  "items": [
    {"id": "...", "kind": "...", "week": 1, "zh": "...", "pinyin": "<sandhi applied>", "en": "...", "note": "...",
     "audio": "audio/<id>.mp3", "audioSlow": "audio/<id>-slow.mp3",
     "fills": [{"fillId": "kafei", "zh": "...", "pinyin": "...", "en": "...", "audio": "...", "audioSlow": "..."}]}
  ]
}
```
`fills` is present only for patterns; each fill is a fully expanded sentence with its own audio (`audio/<patternId>--<fillId>.mp3`).

### Tone sandhi (build-time)
Applied to pinyin syllables aligned with characters:
- 不 bù → **bú** before a 4th-tone syllable.
- 一 yī → **yí** before a 4th tone; **yì** before tones 1–3; unchanged (yī) at the end of a word, or in counting/ordinals (flag `"noYiSandhi": true` on the item).
- 3rd-tone sandhi is **not** written (standard convention).

Alignment: the build splits pinyin into syllables (space and apostrophe separated, or by a syllable splitter) and requires the syllable count to match the Han character count; mismatch is a validation error.

### Audio
- Voice: `zh-TW-YunJheNeural` via edge-tts (run with `uvx --from edge-tts edge-tts`).
- Normal rate and `--rate=-30%` slow.
- Generated only when the file is missing; existing files are never regenerated unless `--force <id>`.
- If `audio/coach/{id}.mp3` exists, the build points `audio` at it (slow version stays TTS).
- Fallback if edge-tts stops working: Azure/Google Cloud TTS (requires key) — out of scope until needed.

### Scheduling
- One FSRS card per (item id, card type). Key: `"<id>:say"`, `"<id>:listen"`, `"<id>:read"`.
- Session queue: due reviews (oldest due first, types interleaved) then new Say-it cards in source order up to the daily new limit. Listen/Read cards enter as new cards when unlocked and do not count toward the new-card limit.
- Items removed from `phrases.json` are ignored (progress retained but not shown).

### Persistence
- `localStorage` key `mandarin.progress.v1`: `{cards: {key: FSRSCardState}, stats: {streak, lastStudyDate, goodCounts: {id: n}}, lastExport, settings}`.
- Every read/write wrapped in try/catch; app works (non-persistently) if storage is unavailable.
- Export/import is a plain JSON dump of that object.

### Updates
- Service worker: network-first for `phrases.json` (falls back to cache offline), cache-first for everything else. New audio files are cached on first play, plus a background pre-cache of all audio listed in `phrases.json` after load.
- Shell cache version bumped by the build whenever frontend files change.

## Hosting

Public GitHub repo, GitHub Pages from `main` branch root. The user installs via Safari → Share → Add to Home Screen.

## Weekly workflow

1. User pastes coach notes into a Claude session.
2. Claude cleans notes into `data/items.json` entries (week N), keeping the coach's Traditional characters and pinyin, adding translations/notes where missing, adding `cat` tags and new patterns where the notes suggest them.
3. `python3 tools/build.py` — validates, generates audio, writes `phrases.json`.
4. Run tests; spot-check in browser at phone width.
5. Commit and push. Phone picks up changes on next open.

## Testing

- Python (`unittest`): sandhi rules, syllable alignment validation, pattern expansion, id uniqueness, audio-skip-if-exists.
- JS (`node --test`, run with `/opt/homebrew/opt/node@18/bin/node` since the default Node is 16; `lib/*.js` are ES modules shared by browser and tests): card generation, unlock rule, pattern fill selection, session queue ordering, store export/import round-trip.
- Manual: browser pane at mobile size — study a session, reveal, grade, audio plays, browse, export/import.

## Out of scope (YAGNI)

- Multi-device sync, accounts.
- Speech recognition / pronunciation scoring.
- Character writing practice.
- In-app phrase editing.
- Anki export (easy to add later from `data/items.json` if wanted).
